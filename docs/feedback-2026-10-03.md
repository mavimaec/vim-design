# FEEDBACK 2026-10-03

## Guidance

The notes below were accumulated from several feedback sessions. Please integrate this feedback to improve the design of the tool. Ensure that interactions are consistent and simple, and use a local claude folder in this repository to accumulate these rulesets for you to build consistently. If you identify inconsistencies in the user experience of the current designs or in proposed UX designs, ensure those inconsistencies are raised to the operator and that there is a plan to address them (they may also be deferred by the operator depending on the issue). Above all, this building design tool must feel intuitive and must be conducive to building design exploration and refinement. Any notes which feel underspecified should be followed-up with questions to guide the observation towards a solution or a conclusion.

## Feedback Notes

- I had heavily edited a wall which contoured a floor plate and which has a concave feature (like a small recessed porch leading to the building entrance); I was having a very hard time placing a door in the recessed wall; when I would click, the door would appear on an unrelated section of the wall. I had similar challenges placing windows.
- When placing openings, they should have a visual marker to designate the local origin point of the opening.
- Camera panning should move the camera up/down/left/right relative to its own position and should not "slide" the camera on an XY plane. The current implementation causes issues when the camera is close to the ground plane and I middle-click to drag; the camera moves very quickly through the building in this case.
- If I am not in "Edit Mode", I should be able to enter "Control Point" selection mode and select and move control points of walls and floors (and pivot points for openings) without selecting an element to "Edit" it; this would let me make broader changes to my building design without having to enter "Edit Mode" for each element. Having a "Control Point" selection mode implies we would also need an "Element" selection mode.
- In the 3D view, when I hold Alt and hover my cursor over a plane (or long-press with my finger in mobile mode), I can click to enter a "Plan" view aligned to that plane
- Also, entering "Room" mode should allow me to edit the rooms on the active level, and add new ones.
- Another thing we need to brainstorm is how to control whether two overlapping control points are merged into a single one; I ran into an issue where I wanted to pull a room away from another one and I was surprised to see that the room's control points had merged with another adjacent room's control points.
- Also the edit panel should appear to the right if the model view in desktop mode; it's annoying to have to reach across the screen to edit an object.
- User should be able to set the project name
- User should be able to set the room color
- A room could act as an attic should coverable by a roof instead of walls
- Room details > "Above the plane" > the slider and buttons don't look like they're working or they're disconnected (one doesn't immediately update the other)
- Width/height/sill -> all numeric inputs should be draggable number inputs (see vim-html-design)
- All openings must have the opacity controlled by the settings of the active level (so that openings below or above the active level are see-through, so they don't distract from the authoring experience of placing openings on the active level)
- (needs more specific description) Hidden walls interfere between an attic room and a normal room (for example, the garage's attic has its walls marked hidden but Natalie's room and Natalie's playroom still need their walls.
